Cybou: A Smarter, Reproducible Operating System

A technical blueprint defining the vision, NixOS architecture, KDE Plasma 6 visual system, staged roadmap and acceptance matrix for Cybou.

Base: NixOS 26.05 Stable Desktop: KDE Plasma 6 (Wayland) Status: Implementation Active Updated: August 2026
Explore Web Landing

1. Executive Summary & Core Vision

Cybou is a smarter personal Linux distribution engineered around reproducibility and spatial design. It operates under a strict release principle: build a trustworthy body first, and earn every capability added after it.

Layer 1: Visual & Technical Body (v0.1)

Declarative NixOS foundation with atomic generation rollbacks, custom KDE Plasma 6 Wayland desktop theme ("Cybou Horizon"), curated default applications, and zero telemetry.

Layer 2: Product foundation (v0.2+)

Welcome and About applications, a readable generation viewer, better recovery, hardware profiles and guided application installation. Still no autonomous behaviour.

2. Architecture & Technical Stack

Cybou combines the immutable, declarative package management of NixOS with modern Wayland desktop infrastructure.

Core System Stack

  • Base System: NixOS 26.05 locked via Nix Flakes (flake.lock).
  • Display & Session: SDDM greeter + KDE Plasma 6 running natively on Wayland.
  • Theme & Aesthetics: Cybou Horizon global theme, dark/light color tokens, custom Aurorae window decorations, and single floating top horizon panel.
  • Audio & Networking: PipeWire audio graph server + NetworkManager for declarative network profiles.
  • Build Output: Bootable NixOS ISO, qemu/KVM virtual machine targets, and Hyper-V development images.

3. Smarter Linux: what comes after v0.1

Cybou earns capability in stages. Nothing below ships in v0.1, and nothing is implemented ahead of the stage that justifies it:

  • Understandable updates: see what changed between two NixOS generations, and why a build failed, without reading raw logs.
  • Recoverable by default: every state is a generation you can return to, so an update is never a one-way door.
  • Private by construction: no telemetry, no account, no runtime downloads — a constraint on every later stage, not a v0.1 detail.
  • Proposals, never surprises: any future system change is a declarative diff presented for approval, applied only by the user.
